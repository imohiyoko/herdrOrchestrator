# pr-queue の公開前検査

`tb pr-queue run` は、PR を作る前に、次の 5 つに規則ファイルを掛けます。

| 対象 | 位置の表記 |
|---|---|
| PR の題 | `title` |
| PR の本文(行ごと) | `body:<行>` |
| コミットメッセージ(base からブランチまでの各コミット、行ごと) | `commit <hash7>:<行>` |
| ブランチ名 | `branch` |
| 差分: 変更したファイルのパス | `path:<パス>` |
| 差分: 足した行 | `diff:<パス>:<行>` |

## 設定(必須)

- `PR_QUEUE_DENY_PATTERNS`(環境変数)か `config/pr-queue.conf` の `deny_patterns` に、規則ファイルの**絶対パス**。環境変数が優先。
- **未設定・読めない・書式が不正・規則が 0 件なら、`run` は何もせず警告して終了コード 1 で止まります(fail-closed)。** 承認済みの行はそのまま残ります。公開か非公開かの判別はしないので、許可リストのリポジトリすべてに掛かります。
- 規則ファイルは社内の名前を含みうるので、この公開リポジトリには置きません。

## 規則ファイルの書式

1 行 1 規則: `<名前> <フラグ> <パターン(ERE)>`。`#` で始まる行と空行は無視。フラグは `i`(大文字小文字を無視)か `s`(区別する)。

```
example-name  i  example-word
example-key   s  AKIA[0-9A-Z]{16}
```

## 例外ファイル(任意)

`PR_QUEUE_DENY_EXCEPTIONS` か conf の `deny_exceptions`(絶対パス)。1 行 1 例外: `<規則名> <ERE>`。その規則に合った**文字列(ヒットした部分)**が ERE に合えば、そのヒットは無視します(大文字小文字の扱いは規則と同じ。厳密にしたいときは `^` と `$` を書く)。

noreply の Co-Authored-By 行を通す例(`email` という名前の規則がある場合):

```
email  ^noreply@example\.com$
```

## ヒットしたとき

PR は作らず、行を `rejected`(`last_error` に「公開前検査: 規則名@位置」)にします。attempts は使いません。`tb notify` が on のときは、規則名と位置だけを警告として 1 件積みます。**マッチした値は、出力にも DB にも通知にも出しません**(パスのヒットでは、位置としてパスが出ます)。直したら登録し直します。

## この検査がしないこと

- `approve` と `scan` では掛けません(run の直前だけ)。
- PR の作成後に本文が編集されることは見ません。
