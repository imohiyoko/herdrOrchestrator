tb pr-queue approve <PQ-n> / reject <PQ-n> [-m 理由]   人だけ。approve は本文・題・差分のガードも通ったときだけ

                              draft のみ・本文が body_root の中の実ファイルで承認後に変わっていない・1 行目が body_first_line に合う(設定時)・
                              秘密らしい値なし・同じ head の PR なし・許可リスト(config/repos.md)のリポジトリ。
                              公開前検査(conf の deny_patterns。必須。環境変数では決めない。題・本文・コミットメッセージ(author / committer を含む)・ブランチ名・差分に掛け、ヒットは却下して規則名と位置だけ通知)。
                              検査の直前に origin と同期し(追跡参照が origin の SHA と一致しなければ止める)、PR_QUEUE_REPO_DIR(clone)の追跡参照で差分も見る(必須。バイナリの変更も人に回す。空・不正なら通さない。CI 設定・AdministratorAccess の追加・秘密らしい値は人に回す)。

                              (scheduler の COMMAND ジョブ。許可リストが空・notify が off なら何もせず 0。初回は基準線の記録だけ)

会話チーム(下書きだけ。送信はしない。文面は DB・記録に書かない。設計と書式: conversation/README.md):
tb conv-route --event E --counterpart C --depth D --severity S --deadline DL [--json] | --stdin [--json]
         構造化した依頼(5 つの区分の名前だけ。本文は受け付けない)を振り分け表(設定 conv-routes)で決める。
         routed なら kind・counterpart・channel・timing・severity。表に無い依頼・未登録の相手の区分は推測せず unregistered(needs_human)
tb conv-routes-set [--shared] [--approve-looser] [--dry-run] < 新しい表   振り分け表を書く(人の端末だけ)。version は今より大きくする。
         今の表と全組み合わせで比べ、未登録 → 振り分け・振り分け先の変更があれば --approve-looser が要る(無ければ終了コード 20)。厳しくするだけならそのまま書ける
tb conv-draft (--route <conv-route --json の出力|-> | --kind K) [--note 一般化した状況] [--ref 参照] [--max-chars N | --request <依頼のファイル>]
         下書きの指示(共通の土台 + 種別のチーム + 採用済みのパターン + 今回の依頼)を出す。チームが無い種別・未登録の依頼は共通の土台だけで、そう書く。
         --note に数字・URL・@・# は使えない(一般化した言い方にする)。TB_CONV_TEAMS=off でチームの層を止める
tb conv-voice <役> --draft F [--request F | --request-chars N]   声の役(direct / empathetic / receiver / brevity)に渡す指示と下書きだけを出す(ほかの役の出力は入れない)
tb conv-voice-check <役> [--draft F --request F] < 役の出力   形を確かめる(多くても 3 点。brevity は 1 行目に長さの判定。--draft/--request があれば実際の長さと突き合わせる)。0 / 1
tb conv-length --draft F --request F   文字数を比べる。0=依頼以下 / 1=依頼より長い
tb conv-kinds [--json]   種別ごとのチームの有無とパターンの数
tb conv-patterns <種別> [--all]   採用済み(--all なら候補も)のパターン
tb conv-lint   共通の土台・声の役・種別のファイル・パターン・振り分け表を確かめる。0 / 1
